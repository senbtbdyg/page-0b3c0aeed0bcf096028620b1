Perspective

分流的理性：专线与普通线路的边界

多数现代网络使用者逐渐意识到，盲目追求节点数量往往带来配置冗余与不可预测的抖动。OKZTWO 在层级构建上采取了一种更为克制的路径：将基础流量池与低延迟专线进行明确的物理或逻辑隔离，而不是把所有用户混杂在同一组中继出口。

这种阶梯设计的核心意义在于负载隔离。当轻量用户仅需浏览与基础媒体消费时，普通节点池足以消化日常负载；而针对跨区域协同、游戏低抖动诉求或全频段高画质串流，则由独立的 IPLC 通道与更高等级的带宽池承载。清晰的边界避免了公用通道被突发大流量冲垮的弊端。

Deployment

终端接入与客户端适配环境

OKZTWO 并不绑定专有外壳程序，而是拥抱开放订阅格式。这意味着用户可以在各自平台选用技术成熟、经受过长期安全审计的通用内核与开源客户端。这种解耦方式保障了连接透明度，也使用户能够在不同设备间平滑迁移分流规则。

桌面工作站 (macOS / Windows / Linux)

支持将订阅链接导入主流内核桌面客户端。通过配置 TUN/TAP 虚拟网卡模式，可实现全系统流量的自动分流与本地网段旁路，满足开发编译、远程终端与日常办公的无缝切换。

移动终端 (iOS / Android)

在移动操作系统中，可通过扫描二维码或直接写入订阅链接完成配置同步。建议启用按应用或域名的分流规则集，以避免非必要流量消耗计划内的月度配额。

网关与旁路路由环境

对于多设备家庭或工作室，可将配置部署于软路由或局域网透明网关。需留意所选套餐的并发设备数量限制，确保并发连接数处于订阅允许的范围之内。

Clarifications

技术释疑与常见问题

OKZTWO 的设备同时在线数量是如何统计的？

并发判定基于活跃网络套接字的公网出口会话。当多台设备在同一局域网网关下汇聚为一个出口 IP 时，通常计为一个端点；若分别使用蜂窝网络或不同外部网络，则每个独立活跃 IP 均会占用相应名额。超过套餐限额可能导致新发请求被临时拒绝。

基础版与旗舰版在节点调度上有什么实质差异？

基础版使用的是常规公网优化链路，适合日常非延迟敏感的网页阅读与基础视频；旗舰版则引入了专用内网互联（IPLC）链路，避开了公网主干拥堵，并针对主流流媒体服务做了原生解析池调度，因此在晚高峰的抖动率和多媒体解析覆盖度上具有更优先级的通道保证。

每月分配的流量配额如何重置？

配额以订阅生效日为起点，按 30 天或账单自然周期循环刷新。未用完的流量配额不作滚存累积；当期用尽后，节点连接将暂时受限，直至进入下一个计费周期或手动变更规格。

企业定制路由功能具体支持哪些需求？

团队版所包含的企业定制路由支持根据业务需求指定专有自治域（ASN）的走向分流，或配合专用自建跳板服务器实现固定出口 IP 白名单通信。具体路由策略需在开通后与客户经理对接下发。
